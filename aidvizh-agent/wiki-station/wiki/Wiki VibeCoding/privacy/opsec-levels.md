# Приватность по уровням: threat modeling вместо Tails ради двух сайтов

# Приватность по уровням

Балансировка строится через **модели угроз (threat modeling)**, а не через паранойю по умолчанию. Иначе получается шизофрения с Tails ради проверки двух сайтов.

## Уровень 1: бытовой / research

- **задача**: скрейпинг, тесты API, просмотр сомнительных ссылок;
- **стек**: чистый профиль Firefox/Brave + обычный доверенный VPN (Mullvad, Proton) или ротационные прокси. Никаких танцев с бубном.

## Уровень 2: серая разработка / изоляция инфраструктуры

- **задача**: аренда серверов под изолированные стенды, покупные аккаунты, регистрация доменов;
- **стек**: антидетект (или нативный чистый профиль) + резидентские прокси под гео + оплата криптой (USDT/XMR) + анонимные почты (SimpleLogin, Proton). Без Cloudflare на критичных узлах.

## Уровень 3: zero trace / hardcore

- **задача**: работа там, где цена ошибки — прямой деанон;
- **стек**: Whonix/Tails + Tor-only + Monero CLI + скрытые сервисы (.onion).

## Почему Cloudflare не подходит для жёсткой анонимности

Это американская корпорация: хранит логи, расшифровывает TLS на своих эджах и сливает по запросу органов. Для zero-metadata режима — не вариант.

## Хардкорный стек изоляции

- **DNS и маршрутизация без корпораций**: DoH/DoT на no-log резолверах (Mullvad DNS, LibreDNS, AdGuard Non-filtering) либо собственный Unbound/CoreDNS на изолированной VPS. Onion-роутинг для прямого доступа без публичных IP и DNS-записей вообще;
- **ephemeral by design**: работа из оперативки без сохранения состояния — Tails / Whonix-Workstation, где весь трафик принудительно заворачивается в Tor на уровне отдельной виртуалки-шлюза;
- **инфраструктура без метаданных**: VPS через регистраторов, не требующих даже email (onion-интерфейс, оплата Monero через CLI-кошелёк). Никаких публичных reverse-proxy третьих сторон, TLS-сертификаты — через DNS challenge, чтобы не светить IP при валидации.

## Приоритет почт и сервисов

1. регистрация без email вообще или по временному алиасу (SimpleLogin, Addy);
2. no-log приватные почты (Proton, Tuta через Tor);
3. покупной прогретый Gmail — только если целевой сервис жёстко блочит анонимные домены.

Для серверов и доменов при требовании приватности по умолчанию предлагать no-KYC оффшоры с криптой, а не дефолтные корпорации.
