# Позиция по тестам: анти-TDD, инварианты постфактум, один smoke на проект

# Позиция по тестам

## Анти-TDD

TDD реально имеет смысл только там, где спецификация высечена в граните: парсеры протоколов, крипта, биллинги, строгая математика. В прототипе, стартапе на коленке, реверсе антифрода или алгоритме с меняющимися каждые полчаса требованиями чистый TDD превращает жизнь в ад и утроит время разработки — больше переписываешь упавшие тесты, чем двигаешь код.

**Запрещён догматичный TDD на каждый чих.** Локальный фикс бага, верстка, UI-логика, интеграция платформенного API — сначала минимальный рабочий код по месту. Тесты пишутся постфактум и только на критические инварианты, если прямо запрошено. Не тратить итерации на тесты до реализации.

## Как выглядит правильный цикл агента

1. **код пишется первым** — точечный фикс;
2. **тесты постфактум, юнит/интеграционные** — строго контракт функции или API;
3. **e2e — один-два счастливых пути (smoke)** на весь проект, чтобы знать, что система вообще стартует, а не гонять браузер на каждую строчку;
4. **жёсткий лимит на запуск**: запрещено запускать полный сьют ради мелкого фикса. Гонять только один упавший файл, максимум 2 итерации, потом стоп и звать человека.

## Что обязан покрывать тест

Тест обязан бить в контракт:

- успешный сценарий (happy path);
- краевые случаи: пустой массив, null, битый UTF-8, переполнение, 0 и отрицательные числа;
- обработка ошибок: сеть упала, таймаут, невалидный JSON.

**Запрещено мокать всё подряд ради зелёных галочек.** Если тест не может упасть при реальном баге в логике — этот тест мусор.

## Запрет на браузерную мастурбацию

Запрещено поднимать браузеры, playwright, xvfb и делать скриншоты на каждый чих при правках верстки и CSS. Геометрия чинится по коду и спецификации CSS (box model, stacking context, scrollbar-gutter). Пиксельный снимок разрешён только в рамках vision-driven реверса (баг верстки, переносов, PDF или шрифтов) либо по прямой просьбе.

## Запрет микро-патчей

Запрещено дрочить файл через 10 вызовов `sed` и inline-replace. Прочитал файл целиком → переписал нужный блок один раз → проверил diff.

## Критерий готовности

Решение задачи юзера, а не вылизывание кода до блеска. Тесты, абстракции, харнессы и рефакторинг — только под конкретный риск или требование. Код на будущее и полировка сверх ТЗ запрещены. Проверка обязана влиять на следующий ход, а не быть ритуалом: для питона — синтакс-чек, на выходах — значимые данные, а не только нулевой код возврата.
