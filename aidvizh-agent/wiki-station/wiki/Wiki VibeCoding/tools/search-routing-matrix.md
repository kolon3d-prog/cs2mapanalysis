# Матрица роутинга поиска

## Куда что

1. **код, API, GitHub, техдоки** → `exa` (поиск по кодовой базе и докам без SEO-шлака);
2. **свежие факты, новости, релизы текущего года** → `web_search` / `tavily`;
3. **выкачать страницу целиком, прочитать доку, спарсить URL** → `firecrawl` / `fetch_url` (чистый markdown без HTML-мусора);
4. **редкие баги, форумы, гео-выдача, железный фоллбэк** → `serper` / `serpapi` (когда AI-поисковики выдают пустоту или галлюцинации);
5. **запрет на зацикливание**: запрещено долбить один и тот же тул, если он вернул мусор — переключайся на альтернативный движок по матрице.

## MCP как сенсоры среды

Подключённые MCP-серверы — прямые органы чувств. Агент сам определяет момент, когда внутренних знаний модели недостаточно:

- задача на свежие факты, API, релизы, ошибки библиотек, доки → немедленный ресерч через MCP **до** формирования ответа;
- задача на внутреннюю логику или чистые алгоритмы → решение локально без сетевых вызовов.

**Запрет на пассивность**: не ждать команды «поищи в сети» или «проверь через MCP». Возникла тень сомнения — молча дёрнуть инструмент, валидировать факт, и только потом выдать результат с опорой на пруф.

## Верификация внешних данных

1. **запрет галлюцинаций внешних данных.** Актуальные версии библиотек, сигнатуры CLI, форматы конфигов, чужие API — запрещено додумывать из головы;
2. **обоснование выхода в сеть.** Поиск оправдан только при нехватке локальных данных или проверке фактов. Спамить запросами по очевидным вещам запрещено;
3. **вывод со ссылкой на след.** Утверждения о внешних сервисах подкрепляются ссылкой на доку или реальным diff/curl-ответом, а не абстрактной уверенностью.

## Триггер 1% сомнения

Задача касается внешних библиотек, архитектурных стандартов, CLI-флагов, версий зависимостей или «как это принято в индустрии» — обязателен веб-поиск. Запрещено выдумывать свои форматы и протоколы, пока не проверен индустриальный стандарт (RFC, официальные доки, свежие треды).

## Не перегружать контекст

Не держать двадцать MCP-серверов: схемы тулов сожрут окно, и модель будет тупить при выборе. Минимальный рабочий набор:

1. веб-поиск / доки (лёгкий API, не тяжёлый браузер);
2. терминал (один доступ к шеллу заменяет десяток плагинов);
3. работа с файлами (чтение/запись/поиск по коду).

Браузер в MCP нужен только для сложных SPA с логином или жёстким Cloudflare. Для чистого ресерча без капч — API-серверы поверх готовых поисковиков и fetcher'ов.
