# Три слоя контекста агента

Самообучающийся `AGENTS.md` без ограничений через три итерации превращается в помойку из сотни противоречивых костылей, где модель запрещает себе то, что разрешила пять минут назад. Лечится разделением на три слоя.

## 1. AGENTS.md (или PROJECT_RULES.md)

Компактный и **чисто про проект**. Только фундаментальное:

- стек;
- команды сборки и тестов;
- архитектурные ограничения;
- железные запреты («только plain C, без классов»).

Модель может предлагать правки, утверждает человек. Файл держится худым: тяжёлые процедуры выносятся в скиллы.

## 2. LESSONS_LEARNED.md (он же GRAVEYARD.md)

Пассивный опыт, короткие запреты и факты. Формат: *что пробовали → почему оказалось говном → какой железный инвариант вывели*.

Примеры:

- «на винде консоль сыпет кракозябры, если не выставить CP_UTF8»;
- «библиотека N ломает обратную совместимость с нашим конфигом»;
- «нельзя звать этот эндпоинт без таймаута — вешает процесс».

Правила: **перед проектированием новой фичи свериться с этим файлом.** Если предлагаемое решение повторяет старый косяк — стоп и смена архитектуры. Файл разрастается — раз в неделю рефакторить и выкидывать неактуальное.

## 3. skills/

Готовые процедуры под повторяющуюся рутину: конкретные сценарии под MCP и CLI, шаблоны миграций, проверки сборки. Скилл — это «чтобы сделать X без ошибок, выполни шаги 1-2-3», а не «не делай так».

## Разница в одну строку

- грабли — «куда не наступать», одна строка в логе;
- скилл — «готовый скрипт, как сделать правильно», цепочка команд с контрактом входа и выхода.

## Главное правило

Не давать модели писать правила «на будущее». Правила появляются **постфактум**, когда что-то реально упало на тестах.

## Связи

- Когда урок превращается в скилл — `ai/skill-crystallization`.
- Что писать в отчёт по итогу — `ai/human-report`.
