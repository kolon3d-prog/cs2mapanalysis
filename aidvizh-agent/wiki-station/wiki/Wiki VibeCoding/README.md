# Wiki — библиотека знаний AGGG2.0

Markdown-библиотека по паттерну **LLM Wiki Карпатого** + **Open Knowledge Format (OKF)** от Google:
агент (build-агент) принимает посты и сам ведёт библиотеку — оформляет файлы с тегами,
обновляет `index.md`, пишет в `log.md`. Человек только кидает посты — остальное делает агент.

## Как это работает

1. Пользователь кидает пост (текст, ссылку, идею) в чат.
2. Агент создаёт файл `Wiki/<тема>/<slug>.md` с YAML-frontmatter (см. схему ниже).
3. Агент обновляет `Wiki/index.md` (каталог) и дописывает `Wiki/log.md` (журнал).
4. Агент пересобирает базу: `python3 db-tools/build.py -r Wiki -o db/wiki.db` — поиск по wiki
   через MCP db-tools (`db: wiki`).

## Структура

```
Wiki/
├── README.md          # этот файл — правила библиотеки (схема)
├── index.md           # каталог всех постов (обновляется при каждом добавлении)
├── log.md             # append-only журнал изменений
├── _templates/        # шаблоны (post.md)
├── ai/                # тематические папки (появляются по мере накопления)
├── coding/
├── tools/
└── ...
```

Правило папок: новая тематическая папка заводится, когда по теме набралось 3+ поста.
До этого посты лежат в ближайшей существующей папке, теги решают поиск.

## Схема frontmatter (OKF-совместимо)

```yaml
---
type: Post                    # тип концепта (обязателен): Post | Insight | Reference | Idea | Howto
title: Короткое название
description: Одно предложение — о чём пост (для поиска и index.md)
date: YYYY-MM-DD              # дата поста/события
tags: [ai, 3d, tencent, agents]   # теги — главный механизм поиска
source: https://...           # ссылка на первоисточник (если есть)
author: @xor_journal          # автор/канал поста
status: stable                # draft | stable | deprecated (по умолчанию stable)
generated:
  by: build-agent/aggg2.0     # кто создал/обновил запись
  at: 2026-08-11T15:30:00Z    # когда
---
```

Обязательное: `type`, `title`, `description`, `date`, `tags`.
Остальное — по возможности.

## Таксономия тегов

Теги — **нижний регистр, без пробелов** (дефис вместо пробела), английские слова.

### Категории (первый тег — категория)
- `ai` — ИИ/ML в целом
- `coding` — разработка, инструменты разработчика
- `tools` — софт, сервисы, утилиты
- `3d` — 3D-графика, генерация, движки
- `hardware` — железо
- `research` — исследования, наука
- `industry` — индустрия, бизнес, рынок

### Предметные теги (примеры, расширяются свободно)
- по технологиям: `llm`, `agents`, `generative-3d`, `video`, `voice`, `gpu`...
- по компаниям: `tencent`, `openai`, `google`, `meta`...
- по типам контента: `news`, `tutorial`, `opinion`, `paper`...

При создании поста агент выбирает: 1 категорию + 2-5 предметных тегов.

## Поиск

- **Быстро (человеку):** `grep -ri "tencent" Wiki/` или открыть `index.md` (там таблица всех постов).
- **Через базу (агенту):** MCP db-tools → `search` с `db: wiki`, или
  `python3 db-tools/search.py -d wiki "запрос"`.
- **По тегам:** grep по `tags:` строке в файлах.

## Правила ведения

1. Файл = один пост/концепт. Не сливать несколько постов в один файл.
2. Имя файла — kebab-case (slug): `tencent-worldclaw.md`.
3. Исходный текст поста сохраняется в теле файла без искажений + добавляются
   ссылки/контекст, если агент нашёл первоисточник.
4. Каждое добавление: файл → обновить `index.md` → дописать `log.md` → пересобрать базу.
5. Устаревшее/неверное — помечать `status: deprecated` или `stale_after`, не удалять
   без спроса (история ценна).
6. Секреты в посты не попадают. Если в посте что-то похожее на ключ/пароль —
   заменить на плейсхолдер `YOUR_API_KEY`.
