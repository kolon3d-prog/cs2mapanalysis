# Компоновка экрана: доминанта, F/Z-сканирование, закон близости

# Компоновка экрана

Нейронка вечно скатывается в одинаковые плитки (bento grid на шесть карточек с иконками), потому что не понимает иерархии данных — льёт весь контент в один котёл.

## 1. Правило доминанты

Запрещено верстать одинаковые блоки 1:1:1. На экране всегда один главный элемент (hero-график, ключевая метрика, большая рабочая зона), занимающий 60–70% площади. Остальные 30% — второстепенный контекст по бокам или снизу.

## 2. Z- и F-сканирование вместо каши

Человек не читает интерфейс по диагонали:

- **верхний бар**: логотип слева, глобальный поиск по центру, профиль и уведомления справа;
- **левая колонка (сайдбар)**: только навигация верхнего уровня, максимум 7 пунктов;
- **центр**: данные и работа;
- **контекстные действия**: привязаны строго к своим блокам, а не висят в воздухе.

## 3. Закон близости

Главный факап — лепить одинаковые `gap-4` и `p-4` везде.

Отступ между связанными элементами (заголовок и его текст) **всегда в 2–3 раза меньше**, чем отступ до соседнего независимого блока. Отступ внутри карточки меньше, чем отступ между карточками.

## 4. Чеклист ревью перед выдачей

- есть ли на экране больше одной яркой кнопки? да — перекрасить лишние в ghost/outline;
- все ли карточки одинакового размера? да — переделать под асимметричную сетку с акцентом на главном;
- понятен ли статус системы за 3 секунды взгляда?

## 5. Вариативность вместо хардкода

Сетка и плотность объявляются токенами под выбранный архетип продукта (см. `design/anti-neuroslop`), а не зашиваются одним набором для всех проектов.
