# Вики

Библиотека знаний живёт в `wiki-station/wiki/<название>`, реестр — в `wiki-station/wikis.json`
(первая запись в реестре — **дефолтная** вика, её и берут инструменты без параметра `wiki`).
Один пост — один файл `<тема>/<slug>.md` с frontmatter, плюс строка в `index.md` и запись в `log.md`.

## Цикл работы: минимум вызовов

1. **`wiki_stats`** — первым делом один вызов: какие вики есть (дефолтная помечена), сколько постов, темы,
   топ тегов, покрытие `index.md`, возраст поисковой базы. Так видно, где вообще искать и не ушёл ли ты в чужую вику.
2. **`wiki_find`** — один вызов на вопрос «что у меня есть про X»: отдаёт топ-N постов **с телом**, описанием,
   тегами, датой и подсказками при пустоте. Пачку формулировок можно отдать сразу:
   `wiki_find(queries: ["vpn", "wireguard", "sing-box tun vps"])` — это по-прежнему один вызов.
3. **`wiki_read`** — только когда нужен полный текст по известному пути/слагу (при промахе подскажет ближайшие названия).
4. **`wiki_add_post`** — если знания в вики нет, а оно того стоит.

Типовой вопрос закрывается одним `wiki_find`, а не цепочкой «поиск → чтение → ещё поиск».

## Пусто — не ошибка

`wiki_find` вернул `count: 0`? Это нормальный ответ: рядом придут `suggestions` (похожие посты) и `notes`
(где искали и почему пусто). Не считай это сбоем и не перебирай формулировки вслепую:
сначала посмотри подсказки, потом `wiki_stats` (какие темы и теги вообще есть), и только затем формулируй иначе.
Если знания реально нет — либо добавь пост, либо честно скажи, что в вики этого нет.

## Свежесть базы

Каждый ответ несёт контекст: `wiki` (имя), `root`, `mode` (`db` или `files`), `posts`, `index_age`, `stale`.

- Если база старше самого нового поста, сервер **сам** пересобирает её один раз. Не получилось — честно отвечает
  `stale: true` и ищет по файлам, о чём пишет в `notes`. Врать про свежесть он не должен и не будет.
- `mode: db` — искали по базе (быстро, по описанию и тегам); `mode: files` — по файлам (медленнее, зато без базы).
- Долги закрываются вручную: **`wiki_build`** — пересобрать базу после массовых правок;
  **`wiki_index`** — пересобрать `index.md`, когда индекс отстал от постов (`wiki_stats` покажет «нет N»).

## Как добавить пост

`wiki_add_post(title, description, tags, body, [topic, slug, source, type, wiki])` — дальше всё сам:
файл, строка в `index.md`, запись в `log.md`, пересборка базы.

1. Поля: `type` (Post | Insight | Reference | Idea | Howto), `title`, `description` (одно предложение), `date`, `tags`.
   Теги — нижний регистр, без пробелов, английские; первый тег — категория
   (`ai`, `coding`, `tools`, `3d`, `hardware`, `research`, `industry`), дальше 2–5 предметных.
   Инструмент сам приведёт теги к таксономии и проверит `type` по списку.
2. `topic` — тематическая папка; если под тему набралось 3+ поста, заводится новая папка, до этого пост идёт в ближайшую.
3. **Дубль**: инструмент сравнивает **заголовок** (а не только путь) с постами вики. При совпадении или сильной
   похожести он файл не пишет, а показывает существующий пост — обогати его отдельным разделом, новый файл не создавай.
   Если это правда другой пост, повтори вызов с `duplicate_ok: true`.
4. Чужой текст поста не переписывай: он идёт в файл как есть, обогащения — отдельным разделом ниже.

## Где искать ещё

1. **`wiki_find` / `wiki_search`** — поиск по базе FTS5 (фолбэк — файлы): главный путь.
   `wiki_search` отдаёт машинный JSON (тот же контракт, что `search.py --json`).
2. **MCP basic-memory** — семантический поиск по проекту `wiki-...` (`search_notes`, `read_note`, `build_context`);
   проект заводится командой `wiki-station install`.
3. **MCP-инструменты вики**: `wiki_stats`, `wiki_list`, `wiki_log`, `wiki_lint`, `wiki_build`, `wiki_index`.
4. **grep** — когда нужен точный литерал: `grep -ri "термин" <вика>/`.
5. **`index.md`** — дешёвый обзор: таблица постов с описанием, тегами и датой.

## Команды станции (терминал и скрипты)

    wiki-station list                    какие вики есть, сколько постов, собрана ли база
    wiki-station open <вика> [страница]  показать пост или index/log
    wiki-station search "запрос"         поиск по базе (FTS5), фолбэк — grep
    wiki-station index [вика]            пересобрать каталог index.md из frontmatter
    wiki-station build [вика]            пересобрать базу поиска (db/wiki.db)
    wiki-station log [вика] [N]          хвост журнала
    wiki-station lint [вика]             обязательные поля, таксономия тегов, расхождения строк index.md с постами
    wiki-station new "Wiki Название"     новая вика (index.md, log.md, шаблон)
    wiki-station install                 скилл + база + подключение к MCP

## Правила

- Не выдумывать: `description` и теги — из содержания поста, а не «по смыслу похоже».
- Файлы — markdown с относительными ссылками; ничего не переименовывать без причины (ссылки в `index.md`).
- Теги сравниваются строго: `AI` и `ai` — разные, `machine learning` и `machine-learning` — тоже.
- После правки постов базы касается `wiki_build`, состава — `wiki_lint`; индекс отстал — `wiki_index`.
