# AGENTS.md

Точка входа для любого агента, который получил этот набор. Здесь **только промты и карта** —
подробности лежат в самих станциях, агент их прочитает сам.

## Карта (чтобы не угадывать)

- `command-center/` — центр: `bin/center.sh` (`status`, `doctor`, `verify`, `outdated`, `update`, `version`, `ps`, `logs`, `docs`, `backup`, `release`, `restore`, `check`, `prereqs`, `fresh`, `bootstrap`, `activate`, `run`), реестр проектов `registry.json`, документация `docs/`.
- станции — `cli-station` (клиенты), `skills-hub` + `skills-station` (скиллы), `mcp-station` (MCP-серверы), `memory-station`, `wiki-station`, `prompt-station`/`sysprompt` (персона и `/prompt`), `modes-station` (режимы `/goal` и `/loop` в opencode2), `vibe-station` (режим директора `/vibe`: воркер-сессии fast/good), `cleanup-station` (снос), `test-center`, `agent-bundle` (харнессы), `camoufox-research` (браузерный ресёрч), `spec-station`, `totp`, `fedora-windows-look`.
- состояние и окружение живут **вне** набора: `~/.venvs/*`, `~/.cache/*`, `~/.local/state/*`, `~/.config/opencode/*`, `~/.agents/skills`.
- авторство и сообщество — `NOTICE.md`.

Правило одно: **сначала спроси систему, потом действуй**. Дисциплина набора — `command-center/docs/11-zero-assumption.md`: не предполагай ОС и окружение, проверяй контракт делом, а не кодом возврата; думай о всей цепочке; честный затык лучше костыля; жди событие (строку лога, статус, хэндшейк), а не время; не выводи по одному файлу — трассируй до места склейки или мутации, а недоказанное помечай `[verify]`; следи за фоновыми процессами без глухих таймаутов (маркер + живость, дамп при провале). `center docs` — карта документации, `center status` — состояние, `center verify` — живая проверка MCP в трёх средах, `center outdated` — что обновить. Не изобретай команд: всё, что нужно, объявлено в реестре.

Быстрый поиск по диску: используй `rg` для текста и `fd` для файлов, всегда исключай `.git`, `node_modules`, `.cache`, `.venvs`, `dist`, `build`, ограничивай вывод `head -N` и глуши ожидаемый `Permission denied` через `2>/dev/null`; несколько терминов ищи одним regex. Голый `grep -r`/`find .` по `$HOME` или корню проекта запрещён. Полный протокол — `command-center/docs/11-zero-assumption.md`.

Тестовый прогон: на микро-правке иди по лестнице 1 → N — один таргет-тест, затем модуль/станция, затем полный финальный гейт ровно один раз перед финальным коммитом или релизом. Полный тяжёлый сьют на микро-правке запрещён. Пакетный прогон делай fail-fast: `bats --abort`, `bun test --bail`; общего bail-флага у `node --test` нет, поэтому пакетная обёртка стопорится по ненулевому `$?`. Каждый запуск синхронный, код пакета перехватывается сразу, лог пишется во временный файл, при провале показывается `tail -n 40`, а выход возвращает сумму статусов. Точный протокол — `command-center/docs/11-zero-assumption.md`.

Апстрим: существующий checkout не клонируется повторно; используй `git worktree` и точечный `fetch --depth=1`, после checkout выведи ревизию, размер и проверь ключевые файлы. Тяжёлые операции не глуши: держи прогресс видимым, а вне TTY включай доступный флаг (`git clone/fetch --progress`, `curl -#`, `rsync --info=progress2`). Подробный протокол — `command-center/docs/11-zero-assumption.md`.

У агента есть собственная инженерная позиция и архитектурное видение: он не ограничивается буквальным повторением запроса, объясняет риски и альтернативы, безопасно обратимые изменения делает автономно, а разрушительные и внешние побочные действия не выполняет молча.

## Тесты

Политика одна: **домен + e2e, больше ничего**. Юниты сверх домена, интеграционные и контрактные слои —
не писать, не добавлять, не требовать. Исключения: инфраструктура и bats-наборы самого набора,
спек-команды (`/spec-bugfix`, `/spec-new` — у них свой контракт с preservation-тестами) и явная просьба
игнорировать политику. Если description скилла (tdd, testing) ведёт в юниты первыми — политика сильнее:
дефолт скилла не применяется, пока не запрошен.

## Промты

Первая установка на новой машине:

```
Прочитай AGENTS.md и центр: command-center/bin/center.sh docs.
Поставь набор с нуля: prereqs → fresh --yes → verify → status.
Серверы с ключами (tier=keyed) не ставь — только базовые.
В конце покажи: что поставлено, что осталось руками, какие проверки прошли.
```

Обновление старой версии на новую:

```
Обновляю набор: было <старая версия>, стало <новая> (файл VERSION).
Сделай: outdated → update (сначала --dry-run, потом всерьёз) → verify → check.
Уже актуальное не переустанавливай; чужие записи в конфигах не трогай;
что нельзя обновить без переустановки — назови отдельно.
Отчёт: что изменилось, что осталось, чем проверено.
```

Работа с центром в текущей сессии:

```
Осмотрись в наборе: center status и center docs.
Разбери проблемные проекты, предложи по каждому одно действие,
выполни только безопасное (без сносов и без переустановок).
```

Живая проверка MCP и браузера:

```
Проверь соединения: center verify (тяжёлые браузерные можно отложить через --exclude).
Если у клиента запись новее запуска — скажи, что нужен перезапуск, и не чини наугад.
Провалы объясни по состояниям: connected / no-handshake / spawn-failed / timeout / http-error.
```

Процессы, логи, занятость:

```
Кто что держит: center ps, при необходимости center logs <проект>.
Если занят браузер — не снимай чужую блокировку, покажи владельца и предложи подождать.
```

Что устарело в доках и цифрах:

```
Прогони bin/docs-check.sh и почини расхождения: числа берутся из кода и реестра, не наоборот.
```

Скиллы (найти, прочитать, поставить):

```
Найди в установленных скиллах то, что отвечает на задачу: bin/skills-station.sh find "<слова>".
Нужный — прочитай (show), отсутствующий — поставь из маркетов (`skills-manager search|inspect|install`; сам хаб — `skills-hub/skills-manager.sh`).
Не пиши свой велосипед, пока не убедился, что скилла нет.
```

Выпуск новой версии набора:

```
Готовим релиз: бампни VERSION по правилу центра (patch|minor|major), прогони center check,
собери архив: DIST_PASSWORD=<пароль из канала> bash ../dist/build.sh (сборщик живёт вне набора,
рядом с AGGG на том же диске; в поставку он не входит).
Пароль в файлы не пиши. В конце покажи имя архива, размер и sha256.
```

Дальше агент читает то, что нашёл сам: `center docs`, README станции, `registry.json`, скиллы, память.
