# prompt-station

Станция прошивок: кладёт системный промт (персону) в клиентов — `omp`, `pi`, `opencode`.
Прошивки берутся из общего каталога персон рядом со станцией, а не копируются: поправил текст —
перепрошил, копий не разводится.

## Что куда кладётся

| клиент | файл | смысл |
|---|---|---|
| `omp` | `<agent dir>/APPEND_SYSTEM.md` (по умолчанию) или `SYSTEM.md` | append — дополняет свои правила харнесса; system — заменяет их |
| `pi` | `<agent dir>/APPEND_SYSTEM.md` или `SYSTEM.md` | то же (механика pi, omp её унаследовал) |
| `opencode` | `<config dir>/AGENTS.md` | глобальные инструкции; у opencode нет «заменить системный промт» файлом — только добавить |

`<agent dir>` — `$PI_CODING_AGENT_DIR` или `~/.omp/agent` и `~/.pi/agent`; `<config dir>` —
`$XDG_CONFIG_HOME/opencode` или `~/.config/opencode`. Ни в одном файле не появляется абсолютных путей
диска: содержимое копируется в клиентский каталог.

## Команды

    bin/prompt-station.sh list                      что есть в каталоге прошивок
    bin/prompt-station.sh show <имя>                текст прошивки целиком (посмотреть до прошивки)
    bin/prompt-station.sh status [--client ...]     что прошито сейчас (имя и хеш) + какие расширения стоят
    bin/prompt-station.sh flash <имя> [флаги]       прошить
    bin/prompt-station.sh revert [--client ...]     снять (вернуть .bak, если был)
    bin/prompt-station.sh verify <имя>              проверить, что прошито именно это
    bin/prompt-station.sh install-ext               расширение «смена персоны на ходу» для omp/pi/opencode
  bin/prompt-station.sh install-ext --force       заменить чужое расширение, предварительно создав .bak

флаги: `--client omp,pi,opencode|all`, `--target append|system`, `--dry-run`.
новая персона — просто положить файл `.txt` или `.md` в каталог прошивок: `list` его сразу покажет.

Личный оверлей (вне набора): `~/.agents/persona-overlay.md`, путь меняет `PROMPT_STATION_OVERLAY` —
личные факты о собеседнике и своё для этой машины. `flash` дописывает оверлей к персне перед записью в
клиентов, `verify`/`status`/`show` сверяют уже склеенное (`status` помечает `+оверлей`). Файл живёт вне
каталога персон, в набор не попадает: у каждого, кто поставит набор, свой оверлей и своя история.
Правка оверлея требует повторной прошивки — `flash` той же командой.

Windows — та же станция без Git Bash:

    pwsh -File bin/prompt-station.ps1 status
    double-click bin/prompt-station.cmd

## Смена на ходу (внутри живой сессии)

Прошивка файла — это база: её клиент читает на старте. Чтобы менять персону **не перезапускаясь**,
станция ставит расширение `install-ext` (один самодостаточный файл `shared/persona.ts` для omp и pi
плюс плагин и команда для opencode). В сессии появляется команда:

    /persona duck        включить персону duck на текущую сессию
    /persona             что сейчас и что есть
    /persona off         снять, дальше отвечаю своим промтом

текст уезжает системным сообщением на каждом запросе (у omp/pi — хук `before_provider_request`,
у opencode — хук `context` с `system.push`), поэтому смена мгновенная и на историю не влияет: переключил —
следующий ответ уже в новой персоне. активная персона живёт в памяти процесса по session id, так что
новая сессия начинается с базовой прошивки.

`install-ext` сначала ставит симлинки: `~/.omp/agent/extensions/persona.ts`, `~/.pi/agent/extensions/persona.ts`,
`~/.config/opencode/plugins/persona.ts`, `~/.config/opencode/commands/persona.md`. Если Windows запрещает
ссылку (`EPERM`/`EACCES`), станция кладёт копии и прямо пишет, что это копии; после обновления источника
установку нужно повторить. opencode подхватит плагин после `opencode2 service restart`, omp/pi — на старте
сессии (или `/reload` у pi).

## Проверка

    bin/prompt-station.sh status     # прошито: <имя> у каждого клиента, код 1 если где-то пусто;
                                     # следом — какие расширения (persona/sysprompt) стоят у трёх клиентов
                                     # и строка про их конфликт
    bin/prompt-station.sh verify <имя>
    bats tests/station.bats          # 23 теста: три клиента, замены через .bak, target=system, revert, dry-run, личный оверлей, расширения persona/sysprompt и конфликт, PS-обёртка

тесты подменяют дом (`PROMPT_STATION_HOME`) и каталог прошивок (`PROMPT_STATION_PERSONAS`) — реальные
конфиги клиентов не трогаются. После прошивки клиентам нужен перезапуск: omp/pi читают файлы на старте
сессии, opencode — на старте сервиса (`opencode2 service restart`).

## Грабли

- **`revert` не «угадывает» прежний промт.** Если файла раньше не было, он удаляется; если был —
  возвращается только из `.bak`, который делает `flash`. Перепрошил дважды — в `.bak` лежит первая
  прошивка, а не исходный текст.
- **У opencode инструкции добавляются, а не заменяют промт.** Свой системный промт он собирает сам,
  `AGENTS.md` приходит поверх; для «жёстко заменить» механизма нет.
- **Личный `AGENTS.md` в проекте сильнее глобального** — если в репозитории лежит свой `AGENTS.md`,
  глобальная прошивка не отменит его, они сложатся.
- **`persona` и `sysprompt` друг о друге не знают.** Оба расширения пишут в системный канал одной
  обёрткой `<system-reminder>`: стоят оба — оба текста уедут в системную роль, порядок будет порядком
  чтения каталога, приоритета нет. Что стоит, показывает `prompt-station status`.
- **Прошивка — это текст, а не настройка.** Ничего не включается флагом и не отключается в UI: чтобы
  понять, что сейчас зашито, смотри `prompt-station status`.
