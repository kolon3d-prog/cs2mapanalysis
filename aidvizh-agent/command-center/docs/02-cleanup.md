# Снос и чистая установка

`cleanup-station` снимает всё, что ставят станции, и не трогает данные на диске.

    cleanup-station plan                      # что будет снято
    cleanup-station clean-all                 # то же, но без --yes это только план
    cleanup-station clean-all --yes           # реальный снос
    cleanup-station clean-skills --layer all  # только скиллы: global/opencode/claude (project — по явной просьбе)
    cleanup-station clean-prompts             # только наши прошивки
    cleanup-station clean-extensions          # только ссылки на диск в каталогах расширений
    cleanup-station clean-mcp                 # только записи серверов в конфигах (с .bak)
    cleanup-station clean-cli --only pi       # снять конкретный CLI пакетным менеджером
    cleanup-station clean-shims               # шимы, которые писались файлом (mcp-keypool, skills-manager)
    cleanup-station clean-locks               # лок установщика скиллов (~/.agents/.skill-lock.json)
    cleanup-station clean-units               # юниты systemd часовой автопроверки
    cleanup-station clean-configs             # конфиги клиентов целиком (спросит «уверены?», без --yes откажет)
    cleanup-station clean-state               # состояние агентов: базы, сессии, кэши
    cleanup-station clean-purge               # логины, настройки, файл ключей (потом вводить заново)

Правила безопасности зашиты в код: работаем только внутри домашнего каталога (или `--home <путь>`);
удаляем ровно известные файлы, ссылки на диск и записи в конфигах; `clean-all` без `--yes` — dry-run;
прошивки снимаются только если их содержимое совпадает с одной из персон (чужой текст не трогаем);
данные на диске — персоны, коллекция скиллов, репозитории — не удаляются никогда.

Чужое в домашнем каталоге тоже остаётся: скиллы снимаются только те, чья запись ссылается на диск
(копии и сторонние ссылки — нет), MCP — только серверы из каталога `mcp-station`, каталога нет — шаг
честно отказывается работать. Личные скиллы и свои MCP-записи `center fresh` больше не сносит;
разбор — в `../../cleanup-station/docs/RESET.md`.

`clean-configs` — единственный шаг, который сносит **чужие настройки**: провайдеров, модели, MCP и прошивки
в конфигах клиентов. Он не запускается молча: в терминале спрашивает `уверены?`, без `--yes` в скрипте
отказывает с кодом 1. Нужен, когда ставишь свои MCP и правила начисто и не хочешь, чтобы остатки
смешивались с новыми.

Что входит в полный снос (`clean-all --yes`): CLI (omp/pi/opencode), наши скиллы во всех слоях
(записи-ссылки на диск), наши расширения и шимы, лок установщика, наши прошивки, MCP-регистрации
из каталога станции, юниты автопроверки. Чужое не входит: личные скиллы-копии, свои MCP-серверы
и правленые прошивки остаются на месте.

Что **не** входит без флагов: состояние агентов (базы, сессии, кэши — это `--state`) и логины
с секретами (`--purge`); вместе их включает `--deep`. Причина простая: без `--state` остаются старые
сессии и статистика, без `--purge` — рабочие логины; первое обычно не мешает, второе экономит вход,
поэтому решает человек.

Типичный сценарий «поставить начисто» — одной командой:

    center fresh            # план: снос → агенты → симлинки хаба → скиллы → MCP → персона → /prompt → проверка
    center fresh --yes      # выполнить (--deep — снести ещё состояние и логины)

`center fresh` останавливается на первом упавшем шаге и печатает, что чинить; в конце — что остаётся руками:
логины провайдеров, ключи сервисов, перезапуск клиентов.

Установщик дистрибутива (`install.sh` / `install.ps1` из архива) делит это на три входа: без флагов —
первая установка (если агентская среда уже есть, ничего не сносит и объясняет, что делать), `--update` —
обновление без сноса (`center update all`), `--reset` — `center fresh --yes`. Что снимается и что
не трогается — в `../../cleanup-station/docs/RESET.md`.
