> (облачного) замера — это помечено. Ориентир владельца: обойти tavily/exa по

## 1. TL;DR — что звать

| Задача | Тул | Аргументы, решающие полноту |
|---|---|---|
| Один URL, дёшево | `fetch_page` | дефолт `max_chars=12000`, `article_only=True` |
| Один URL, максимум текста | `fetch_page` | `max_chars=40000…100000` |
| 10–50 URL за раз | `batch_fetch` | `max_chars=6000…40000`, `article_only=True` |
| Весь сайт | `crawl` | `max_pages`, `max_depth`, `max_chars`, `article_only=True` |
| Много разных домены | `research` / `research_start` | `target_domains=20…60`, `domains_limit=2`, `fetch_all=True` |
| PDF/DOCX/XLSX | `read_document` | `max_chars=40000…100000` |

## 2. Три рецепта

**«Быстро» — ответ за один ход, ~12k символов на источник (дефолт тулов на
срез 21.09): годится, когда нужен факт/абзац, а не корпус.**

```python
web_search(query="...", max_results=10)             # топ выдачи
fetch_page(url, max_chars=12000, article_only=True) # 1 страница
```

**«Полно» — корпус по теме, 30–50 источников, ~10–40k символов на источник:**

```python
research(queries=["тема", "тема comparison"],       # несколько формулировок
         target_domains=20, domains_limit=2,        # 20 РАЗНЫХ сайтов, ≤2 на домен
         expand=True, terms_wave=True, quality_first=True,
         academic=True,                             # arXiv + Semantic Scholar (tier 0)
         fetch_all=True,                            # тексты ВСЕХ отобранных, не топ-N
         article_only=True, max_chars=6000, as_json=True)
```

`fetch_all=True` — ключ к полноте: без него возвращаются сниппеты, с ним — текст
каждого источника (цена: браузерный проход по каждому URL). Если тексты уже есть
списком URL — `batch_fetch(urls=[...], max_chars=6000, article_only=True)`:
30–50 URL одним вызовом, батч ≥8 идёт параллельно, на один домен ≤2 запроса.

**«Глубоко» — корпус + документы + ленивый контент, часы, но максимум полноты:
кампания в фоне (`research_start(..., background=True)`) + выжимки + документы.**

```python
research_start(topic="тема", queries=["тема", "тема обзор"],
               target_sources=60, domains_limit=2, background=True)
# → ждать МАРКЕР ~/.cache/camoufox-research/exports/<camp_id>.json, не поллить
research_status(camp_id) → research_report(camp_id) → research_digest(camp_id)
batch_fetch(urls=...)            # тексты отобранных
read_document(source=`/pdf/<id>`, max_chars=100000)   # PDF/DOI без .pdf в пути
citation_pack(camp_id) → citation_report(camp_id)     # только verified ✅
```

## 3. Контент: замеренные цифры

Все замеры — драйвер MCP по stdio, пакет из репозитория, 21.09.2026 (файлы
замеров `content_*.json` в каталоге прогонов). Токены — оценка `символы / 4`.

| Тул и аргументы | Символов | Секунд | ≈токенов | Что это |
|---|---|---|---|---|
| `fetch_page` Wikipedia, навигация в теле | 30 540 | 8.86 | ~7.6k | без `article_only` — меню/баннеры в тексте |
| `fetch_page` Wikipedia, после потолка 100k | **26 301** | 8.25 | ~6.6k | ВЕСЬ текст статьи (страница короче потолка — резать нечего); до правки было ровно 12 000 |
| `fetch_page` длинная статья, `docs.python.org` (asyncio) | 42 330 | 4.96 | ~10.6k | тоже весь текст страницы: потолок 100k не режет то, что короче него |
| `batch_fetch` 1 URL / 5 URL из кэша | 31 504 / 54 598 | 8.54 / 1.70 | ~7.9k / ~13.6k | тот же материал батч-путём; 0.34 с/страница на 5 URL — только из кэша (24 ч) |
| `read_document` PDF по URL | **40 000** | 2.91 | ~10.0k | ровно `max_chars`, документ длиннее |
| `research` 1 запрос, без `fetch_all` | 10 760 | 1.73 | ~2.7k | сниппеты+структура, без текстов |
| `research_start` кампания «60 доменов» | — | **63 домена / 72 источника** | — | 2 волны, бюджет поиска 3/40 вызовов |

Сколько вообще можно попросить: вентиль `CAMOUFOX_FETCH_LIMIT` (по умолчанию
**100 000** символов — и это же потолок кэша), а `max_chars` вызова режет ответ
клиенту. До 21.09 стоял жёсткий `_FETCH_LIMIT = 12000`: `fetch_page(max_chars=30000)`
возвращал ровно 12 000, и обрезанный текст лежал в кэше сутки — «дай больше» не
работало ни на первом, ни на повторном вызове.

## 4. Против облаков

Замеры одной сессии 21.09.2026: одинаковые URL, наш `fetch_page`/`read_document`
против tavily/exa. Облачные цифры — из ответов API, зафиксированы в контексте
сессии (файлом не сохранены); наши — из файлов замеров выше.

**Метрика «полнота»** (определяем явно, иначе спорят числа, а не смысл):
(1) сколько символов корпуса даёт один вызов, (2) сколько РАЗНЫХ домены в одной
кампании, (3) сколько стоит повторный заход за тем же текстом.

**Как читать таблицу.** Болд — наше значение, а НЕ «победа»: по сырым символам
одной страницы мы в паритете (exa выше на Wikipedia, tavily на PDF; разрыв
≤10–30 %) — превосходства по этому пункту нет. Выигрыш в пунктах (2) и (3) плюс
потолок: страницу можно забрать целиком (100k), и повтор ничего не стоит.

| Цель | camoufox-research | tavily | exa |
|---|---|---|---|
| Wikipedia, статья | **26 301** симв. | 20 096 | 29 577 |
| PDF-документ | **40 000** симв. (ровно запрошено) | 40 113 | 37 132 |
| Разных домены за одну кампанию | **63 домена / 72 источника** | не заявляет доменный таргет | не заявляет |
| Повторное чтение той же страницы | **0 токенов** (`delta=True` / кэш 24 ч) | тарифицируется заново | тарифицируется заново |

Где полнота наша: **потолок 100k** вместо чужих 7–30k на страницу (у tavily PDF
доходит до ~40k — на документах запас в 2.5 раза, на страницах в разы); **корпус
вместо топов** (`fetch_all=True` + `target_domains` + волны → 63 сайта за
кампанию); **документы целиком** (arXiv/DOI-ссылки без `.pdf` в пути); **повтор
бесплатен**; **живой браузер** (JS/SPA, клики, формы, ленивые ленты, логин);
**данные не уходят третьей стороне**.

Где облака сильнее (честно):

- **Семантический поиск по смыслу** — exa ищет по эмбеддингам, у нас выдача
  поисковика + волны термов (`terms_wave`) — это обход, а не семантика.
- **Скорость одиночного ответа**: у них индекс; наш первый холодный `fetch_page`
  = старт браузера (`boot ≈ 0.85 с` — замер soak) + сеть;
  **инфраструктура**: у них пул IP/прокси «из коробки» — у нас дом/машина владельца.
- **Сразу готовый ответ-синтез** (answer/generation) — у нас синтез делает агент.

## 5. Рычаги полноты

| Рычаг | Значение | Что делает |
|---|---|---|
| `CAMOUFOX_FETCH_LIMIT` | 100 000 (дефолт) | сколько символов вообще забирать и хранить в кэше |
| `max_chars` | вызов | сколько вернуть клиенту (режет то, что уже забрали) |
| `article_only=True` | `fetch_page`/`batch_fetch`/`crawl` | текст статьи без меню/баннеров (Trafilatura + fallback) |
| `fetch_all=True` / `fetch_top=N` | `research` | текст ВСЕХ отобранных, а не топ-N / прочитать топ-N сразу |
| `target_domains` / `domains_limit` | `research`/`research_start` | цель по РАЗНЫМ сайтам и предел на домен |
| `expand` / `terms_wave` / `quality_first` | `research` | волны переформулировок, редкие термы, доки/arXiv первыми |
| `academic=True` | `research` | arXiv + Semantic Scholar — первоисточники (tier 0) |
| `delta=True` / `page_diff` | `fetch_page` | повтор дешевле: маркер вместо текста, если не изменилось |
| `batch_fetch` ≥8 URL | — | параллельно (заявлено в докстринге «~3×», своего замера нет; per-domain ≤2!) |

Развилка по объёму: 1–2 страницы — `fetch_page`; 10–50 — `batch_fetch`; сайт —
`map_site`/`sitemap` → `crawl`; много домен — `research*`.

**Дефолты тулов (срез 21.09, из живой схемы, а не по памяти):** `fetch_page` /
`batch_fetch` / `research` — `max_chars=12000` (21.09 подняты с 4000: дефолт-обрезок
был ниже облаков), `crawl` — 4000, `read_document` — 6000; `article_only` по
умолчанию `False` у `fetch_page`/`batch_fetch`, `True` у `research`/`crawl`.
Проверить свою сборку: `python -c "from camoufox_research.camoufox_research import mcp;
print(mcp._tool_manager._tools['fetch_page'].parameters['properties']['max_chars'])"`.

## 6. Документы

`read_document(source, max_chars)` берёт PDF/DOCX/XLSX. Расширение в URL — только
подсказка: формат определяется по **магии байтов** (`%PDF`, `PK\x03\x04` → zip →
docx/xlsx). Это принципиально для полноты: ссылки вида `arxiv.org/pdf/2604.11487`
(и любые DOI/журнальные эндпоинты) раньше отбивались ошибкой «формат '.11487' не
поддерживается» — то есть ровно там, где облака отдают мало, мы не читали вообще.

- `max_chars=40000…100000` — документ обычно длиннее страницы, ставьте с запасом;
  старые `.doc`/`.xls` не читаются (`libreoffice --convert-to docx/xlsx`).
- Скачанный файл (`session_download` → путь в кэше) читается тем же тулом по пути.

## 7. Ленивый контент

Ленты с подгрузкой (`infinite scroll`) одной высоты не отдают весь текст:
`session_scroll(direction="down")` — 0.8 экрана + ожидание стабилизации
(lazy-догрузка), `direction="bottom"` — сразу в низ. Цикл:

```python
session_start(url="https://.../feed")
for _ in range(N):            # до исчезновения прироста
    session_scroll(direction="down", max_chars=6000)
session_text(max_chars=40000)
session_end()
```

Opt-in профиль (`--caps research,browser,session`): без `session_start` вызов
падает — сессия живёт состоянием вкладки.

## 8. Кампания 60+ доменов

Живой замер 21.09: `research_start(topic="self-hosted browser automation platforms 2026",
target_sources=60, domains_limit=2)` → **источников 72, разных сайтов 63/60**,
2 волны, бюджет поиска **3/40** вызовов, статус `done`.

Термины (чтобы числа читались одинаково): **источник** — URL в базе кампании (их
72); **домен** — уникальный сайт (`docs.python.org` + `peps.python.org` = один,
поэтому 63 < 72); **волна** — один проход по запросам (база → доборка редкими
термами → пагинация; в замере хватило двух); **бюджет поиска** — счётчик вызовов
поисковика по кампании (`3/40` = 3 из лимита 40).

Дальше фазы:

| Фаза | Что | Время |
|---|---|---|
| Кампания | волны поиска → домены → база | 5–60 с (сеть/DDG) |
| Выжимки (`research_digest`) | `batch_fetch` по URL через браузер | ~1–3 с **на URL** |
| Verify (`citation_pack`) | HEAD/GET, 10 потоков, таймаут 6 с | 0.1–10 с, TTL-кэш сутки |

Времена фаз — из замеров проекта (`docs/README.md`, «Как читать охоту»), не из
этого захода: ориентир, а не воспроизводимая команда. Не поллить: кампания
пишет маркер `<camp_id>.json` — ждать файл. Вторая нога поиска:
`feeds=[rss/sitemap]` собирает источники без поисковика.

## 9. Токен-бюджет

Оценка `символы / 4`: дефолт `max_chars=12000` ≈ 3k токенов на страницу (30
источников ≈ 90k); «полно» `max_chars=40000` ≈ 10k токенов (10 источников ≈ 100k);
потолок 100k ≈ 25k токенов за страницу — только под конкретный вопрос;
`delta=True`/`page_diff` на повторе ≈ 0; `research(as_json=True)` отдаёт тот же
объект в `structuredContent` (текстовая форма остаётся в `content`).

Правило: точный вопрос — точный `max_chars`; «выжимаю полноту» — читать много
источников дешевле, чем один глубоко. Дорогое (картинки `screenshot`) — только
после `snapshot`/`fetch_page`.

## 10. Пределы и ловушки

- **Кэш 24 ч**: повторный `fetch_page` мгновенный, но СТАРЫЙ момент времени —
  для «что нового» нужен `delta=True`/`page_diff`.
- **`check_links` последовательный** (таймаут 15 с на КАЖДУЮ ссылку; 50 ссылок —
  арифметически ≈12 мин, замером не подтверждено) — бюджет вызова и таймаут
  клиента ставьте ≥900 с; `crawl` тоже длинный.
- **Капча/rate limit**: батч защищён per-host лимитом ≤2, но злоупотребление
  шириной = капча; капча/403 — сигнал СТОП, а не приглашение эскалировать.
- **Один воркер = один браузер**: параллельные кампании запрещены законом
  одного инстанса (гонки/EPIPE). Демо Cloudflare Turnstile вживую может отдать
  «Performing security verification» — часть сайтов честно не читается
  (`docs/anti-bot-matrix.md`).

## 11. Воспроизвести замеры

```bash
DRIVE_OUT=/tmp/out.json ~/.venvs/camoufox-research/bin/python scripts/mcp_drive.py \
  /run/media/admin1/DATA/AGGG/camoufox-research \
  '[{"tool":"fetch_page","args":{"url":"<URL>","max_chars":40000}}]'
CAMOUFOX_CAPS=research,browser,session ~/.venvs/camoufox-research/bin/python scripts/mcp_drive.py . \
  '[{"tool":"batch_fetch","args":{"urls":["…"],"max_chars":20000},"full":true}]'  # полный ответ
```
(`scripts/mcp_drive.py` — драйвер MCP по stdio: план — JSON-массив шагов, `DRIVE_OUT` — файл с
ответами.) Смотреть: `chars` (полнота), `sec` (стоимость), `isError`. Полнота
добычи как метрика — `python scripts/bench_truth_recall.py --sample 30` (см.
README, «Benchmarks — truth-recall»).

См. также: `docs/agent-usage.md` (реестр тулов, циклы, границы),
`docs/VERIFICATION.md` (что проверено и как), `docs/anti-bot-matrix.md` (матрица
защит), `docs/landmines.md` (20+ граблей).
