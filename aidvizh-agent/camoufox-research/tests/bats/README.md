# bats-тесты стражей (tests/bats)

Стражи (`gitleaks-precommit.sh`, `git-pre-push.sh`, `install_cron.sh`,
`health_pulse.py`) — это то, что решает «уйдёт ли приватное в публичный репо»
и «побеспокоят ли владельца ночью». Их проверяют настоящим запуском, а не
моками питона: bats зовёт сами скрипты, подсовывая фальшивые внешние утилиты.

## Запуск

```bash
scripts/run_bats.sh      # или из корня репо:
bats tests/bats/
```

Нужны `bats` (≥1.5 — используется `BATS_TEST_TMPDIR`), `git`, `python3`.

## Что покрыто

| Файл | Проверяет |
|---|---|
| `gitleaks_precommit.bats` | rc сканера доходит как есть (1 и 42), чистый скан = 0, нет бинарника = 0 + «CI догонит» |
| `git_pre_push.bats` | пуш нового бранча с `research/private.md` — СТОП; только витрина/метрики — пропуск; границы `--classify` |
| `install_cron.bats` | `--dry` не зовёт crontab; `--dry --keep-timings` только ЧИТАЕТ; своё время не перезаписано; опечатка флага отвергнута; нет crontab — честный отказ |
| `health_pulse_notify.bats` | без согласия/экрана уведомление не спавнится, с ними — уходит ровно один раз на состояние |

## Приём и герметичность

- Фальшивый бинарник кладётся первым в `PATH`, а `PATH` отдаётся скрипту
  **целиком** — реальный `gitleaks`/`crontab`/`notify-send` недостижим.
- Свой `HOME` (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`) —
  чужие `~/.gitconfig` и `core.hooksPath` не влияют на фикстуру.
- Всё пишется в `BATS_TEST_TMPDIR`; `CAMOUFOX_CACHE_DIR` → песочница,
  живой кэш владельца и его `crontab` не трогаются. Сети нет.
- Если тест «молчит, что уведомления нет», рядом стоит положительный
  контроль (с экраном) и проверка «пульс отработал» — иначе молчание
  зеленеет и тогда, когда до проверяемой ветки код не дошёл.

## Тест обязан уметь падать

Зелёный с первого раза ничего не доказывает, поэтому после правок полезно
прогнать мутационную проверку: скопировать `scripts/` + `tests/bats/` в
`/tmp`, сломать один забор и убедиться, что упал именно его тест. Так были
пойманы две пустышки: (1) «нет согласия» не отличалось от «нет экрана»,
пока экран не добавили в негативный тест; (2) стражи на `exec` проверялись
дописыванием `exit 0` — правка, которая ничего не ломала.

## Находка (уже починена владельцем файла)

`tests/test_guard_scripts.py::CronDryRunTest` был **ложно-зелёным**: фикстура
возвращала `calls` из `with tempfile.TemporaryDirectory()`, песочница
удалялась на выходе из `_run`, и `assertFalse(calls.exists())` смотрел в
удалённый путь — тест не мог упасть, даже если `--dry` начнёт писать
crontab. Поймано мутационной проверкой bats (снятие dry-ветки не уронило ни
одного питона). На момент этой правки тест переписан: `tempfile.mkdtemp` +
`addCleanup`, проверяется СОДЕРЖИМОЕ вызовов (dry может читать `-l`, но не
писать), плюс отдельный `test_dry_alone_never_writes`. Дубль контракта в
`install_cron.bats` оставлен намеренно: bats проверяет ещё и то, что запись
не уходит в живой crontab владельца.
