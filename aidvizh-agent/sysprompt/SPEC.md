# SPEC: sysprompt

Контракт фичи `/prompt`. Общий для всех харнесов, реализуется отдельным адаптером под каждый рантайм.

## Интерфейс

    /prompt <текст>    добавить текст в системный контекст текущей сессии
    /prompt clear      сбросить буфер сессии (алиас --clear)
    /prompt            пустой вызов — подсказка по формату

Тексты подсказки и подтверждения фиксированы:

- пусто: `sysprompt: текст пустой. Формат: /prompt <текст>, сброс: /prompt clear.`
- clear: `sysprompt: буфер очищен.`

## Маркер

Команда разворачивается в `<sysprompt>$ARGUMENTS</sysprompt>`. Адаптер обязан распознать маркер,
срезать обёртку и не показывать теги ни пользователю, ни модели. Текст остаётся в сообщении как есть.

## Семантика

- Буфер привязан к сессии (sessionID). Несколько вставок складываются стопкой.
- Текст подставляется в системную часть запроса к модели на каждом шаге сессии, пока жив буфер.
- Буфер живёт в памяти серверного процесса: `/prompt clear` или рестарт его очищают.
- Конфиги, AGENTS.md и файлы проекта не пишутся и не меняются.
- После clear текст, уже осевший в истории диалога, остаётся там; для полного сброса — новая сессия.

## Обязательства адаптера

- Текст обязан попадать в системный канал. Если рантайм не даёт системного канала, деградация до
  user-сообщения допустима, но должна быть явно описана в README харнеса.
- Ошибки в хуках не должны ломать обычные сообщения сессии: всё в try/catch, без падений запроса.
