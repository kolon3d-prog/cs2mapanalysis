# modes-station

Это skill для станции `modes-station`, а не для OMP. Все команды ниже исполняются в opencode2.

## Назначение

- `/goal` ведёт одну активную цель через видимые и скрытые ходы.
- `/loop` повторяет prompt по числу, времени или условию.
- Цель и цикл могут храниться одновременно в конверте состояния V2.
- Завершение цели выполняет только инструмент `goal({op:"complete"})`.

## Перед запуском

1. Любая команда `/goal ...` блокируется в native plan, paused plan или vibe.
2. У инструмента `goal` проверка режима есть только у `op:"create"`. Для `get`, `complete`, `resume`, `drop` и `todo` её нет.
3. `/loop` разрешён в plan и vibe.
4. Уже активная цель не перепроверяет plan/vibe перед каждым продолжением.
5. Первый objective команды `/goal` видимый. Последующие продолжения цели скрытые.
6. Повтор тела `/loop` видимый.
7. `goal.enabled` и `goal.continuationModes` не читаются: таких публичных полей в OpenCode V2 нет.

## Цель

### Запуск

```text
/goal закончить и проверить миграцию
/goal закончить миграцию --turns 8 --tokens 120000
/goal set новая цель после закрытия старой
/goal budget 80000
/goal pause
/goal resume
/goal drop
/goal show
```

Без `--turns` у цели нет скрытого предохранителя. Тест доводит V2 до 1005 ходов и только затем закрывает цель инструментом.

### Завершение

```json
{"op":"complete"}
```

Не закрывай цель текстом `GOAL: DONE`. В V2 этот текст игнорируется. Команда `/goal done` тоже не закрывает цель.

### Инструмент `goal`

Инструмент `goal` динамический:

- отсутствует без цели и guided-интервью;
- появляется при незавершённой цели;
- удаляется, когда незавершённых целей и интервью больше нет;
- во время интервью допускает `op:"create"`.

Публичный предел V2: регистрация инструмента считается для всего экземпляра адаптера. Незавершённая цель в другой сессии может сделать его видимым и здесь. Операции всегда используют `sessionID` текущего вызова; `op:"create"` разрешён только в текущем guided-интервью.

`op:"create"` создаёт goal с `pendingFirst=false`. Поэтому созданная инструментом цель начинает работу со скрытого продолжения. Видимый первый objective получают только `/goal <objective>` и `/goal set <objective>`.

### Бюджет

Учитываются `input + output + cache.write`. `cache.read` не учитывается.

```text
/goal работа --tokens 5000
/goal budget 10000
/goal budget off
```

Смена бюджета не сбрасывает расход. После достижения лимита статус становится `budget-limited`. Сначала подними бюджет, потом вызови `resume`.

Время только показывается. Скрытого лимита времени у `/goal` нет.

### Скрытое продолжение без инструментов

Скрытое продолжение без вызова инструментов не зацикливается:

1. Цель ждёт ручной prompt.
2. Следующий ручной prompt завершает свой ход.
3. После него снова разрешены скрытые продолжения.

Первая видимая objective под это правило не попадает.

## Цикл

### Разбор аргументов

```text
/loop 5 задача
/loop 10m задача
/loop 1h30m задача
/loop 30m1h2s задача
/loop 2 hours задача
/loop 20 --until 'bun test' задача
/loop 20 --while 'test -f .git/index' задача
```

Поддерживаются точные единицы:

```text
s sec secs second seconds
m min mins minute minutes
h hr hrs hour hours
```

Разрешено только одно условие. Значение читается теми же правилами shell, что и в OMP: кавычки и экранирование обрабатывает `readShellWord`.

- `N` — N переотправок плюс первый ход.
- `duration` — дедлайн от момента команды.
- `--while` идёт дальше при коде `0`.
- `--until` останавливается при коде `0`.
- Код `1` даёт противоположное решение.
- Код больше `1` или таймаут — честная ошибка, цикл выключается.
- Условие проверяется после первого выполненного хода.
- Каталог условия берётся из `session.get().location.directory`.

`--compact` поддерживается. `--reset` не поддерживается.

### Остановка

```text
/loop
/loop off
/loop stop
/loop clear
```

Повторный `/loop` выключает текущий цикл до разбора аргументов. `/loop off` — тот же путь. Прерывание хода ставит цикл на паузу и оставляет его включённым; следующий ручной prompt заменяет тело.

## Цель и цикл

Они лежат в одном файле:

```text
version: 2
goal?
loop?
revision
```

Плоские поля в state — старая проекция для совместимости. Источник истины — вложенные `goal` и `loop`; при конфликте плоская проекция отдаёт незавершённую цель.

Порядок:

1. Первый objective `/goal` отправляется даже при активном loop.
2. Пока loop включён, он владеет очередью.
3. Скрытые продолжения цели ждут.
4. После `/loop off` цель продолжает работу.

## Восстановление

- Состояние v1 автоматически мигрирует в V2.
- v1 `GOAL: DONE` мигрирует как незавершённая пауза.
- `turnsLimited=false` не наследует старый предохранитель `1000`.
- После рестарта чужая активная цель переходит в `paused` и ждёт `/goal resume`.
- Старый цикл другого процесса удаляется, чтобы не остался драйвер-зомби.
- Расход, время и todo цели сохраняются при pause/resume/drop.
