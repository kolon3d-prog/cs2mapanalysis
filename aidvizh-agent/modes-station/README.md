# modes-station

Автономные `/goal` и `/loop` для **opencode2**. Цель станции — повторить разбор аргументов, счётчики и условия OMP там, где opencode2 даёт такой API, но не обещать полный паритет внутренних режимов.

- Текущая версия адаптера в `plugin/opencode/modes.ts`: `2.1.0-review`.
- Версия файла состояния: `2`.
- OMP здесь только источник форматов и правил. В opencode2 доступны команды станции, а не команды OMP.

## Команды

```text
/goal [objective] [--turns N] [--tokens N]
/goal set <objective> [--turns N] [--tokens N]
/goal budget <N|off>
/goal show
/goal pause | resume | drop
/goal todo <текст> | todo done N | todo list | todo clear
/goal guided [черновик]
/guided-goal [черновик]

/loop [count|duration] [--while|--until '<cmd>'] [prompt]
/loop off
```

`/goal done` принимается только для ясного отказа: завершает цель исключительно `goal({op:"complete"})`.

Примеры:

```text
/goal закончить и проверить миграцию
/goal закончить миграцию --turns 8 --tokens 120000
/goal budget 80000
/loop 5 почини тесты
/loop 10m собирай отчёт
/loop 20 --until 'bun test' почини тесты
/loop 20 --while 'test -f .git/index' повторяй сборку
/loop 3 --compact проверяй документацию
```

`/loop` без тела вооружает цикл. Следующий ручной prompt становится его телом и первым ходом.

## Разбор аргументов

### Цель

`parseGoalInput` принимает положительные безопасные целые числа для `--turns` и `--tokens`. Без этих флагов у цели нет скрытого лимита ходов.

Команда создаёт цель из:

```text
/goal <objective>
/goal set <objective>
```

### Цикл

Текущий разбор `parseLoopArgs` повторяет закреплённые в адаптере ветки OMP:

- `N` — положительное безопасное целое число переотправок; первый ход идёт сверху и не тратит переотправку.
- Длительность принимает единицы `s`, `sec`, `secs`, `second`, `seconds`, `m`, `min`, `mins`, `minute`, `minutes`, `h`, `hr`, `hrs`, `hour`, `hours`.
- Поддержаны составные значения: `1h30m`, `30m1h2s`.
- Поддержана раздельная запись: `2 hours`.
- Экспортированная `readShellWord` повторяет OMP `readShellWord`: склеивает соседние кавычки, снимает экранирование и различает одинарные и двойные кавычки.
- Разрешено только одно из `--while` или `--until`.
- Значение условия читается только как shell-слово. Незакрытая кавычка, пустое условие и неизвестный флаг останавливают разбор.
- `--compact` — расширение адаптера. `--reset` отклоняется: opencode2 не умеет переводить текущую вкладку в новую сессию.
- В V2 нет публичного `session.info.settings`; `goal.enabled`, `continuationModes` и `loop.mode` не читаются из выдуманного поля. Настройки этих функций — отдельный platform limit.

В палитре opencode2 подсказка находится в статическом `description` команды. Отдельного ghost-текста и живого статуса по сессии этот адаптер не создаёт.

## `/goal`

### Видимая цель и скрытые продолжения

Команда `/goal <objective>` или `/goal set <objective>` создаёт состояние с `pendingFirst=true`. Координатор отправляет первый objective через обычный `session.prompt`:

- он виден как пользовательский prompt;
- если цикл уже владает очередью, goal получает приоритет и не превращает objective в тело цикла;
- после первого хода продолжения отправляются через `session.synthetic({resume:true})` без `description`, то есть скрыты;
- запасного видимого продолжения у `/goal` нет.

Каждое продолжение получает отдельный `<goal_context>` через hook `context|generate`. В нём есть objective, токены, время, явный лимит ходов и todo.

Особенность V2: `goal({op:"create"})` создаёт цель с `pendingFirst=false`. Поэтому интервью, в котором модель вызывает tool напрямую, начинает драйвер сразу со скрытого продолжения. Видимый первый objective гарантирован именно для команд `/goal` и `/goal set`. Guided-интервью теперь отправляет свой kickoff через `session.synthetic({resume:true})`: модель ведёт диалог, задаёт ровно один вопрос за turn и вызывает `goal({op:"create"})` после заполнения полей.

### Завершение

Единственный путь завершения — `goal({op:"complete"})`.

- Текст `GOAL: DONE` не закрывает активную цель.
- Команда `/goal done` не закрывает цель.
- Старый v1-файл с `reason:"GOAL: DONE"` мигрирует как незавершённая пауза, а не как успех.
- `pause`, `resume` и `drop` сохраняют расход, время и todo. Завершённую или снятую цель нельзя возобновить.

### Лимиты и бюджет

- `--turns N` — единственный лимитирующий счётчик ходов.
- По умолчанию `turnLimit` отсутствует. В текущем V2 нет скрытого предохранителя в 1000 ходов.
- `--tokens N` и `/goal budget N|off` задают бюджет токенов.
- Считаются `input + output + cache.write`. `cache.read` не считается.
- Смена бюджета сохраняет накопленный расход.
- После исчерпания цель получает статус `budget-limited` и ждёт нового бюджета. Плагин отправляет один скрытый `BUDGET LIMIT` steer на поколение цели: модель должна только завершить проверку и не выдавать частичный результат за completion. Если public tool hook недоступен, сам status и truthfulness сохраняются, но точный post-tool accounting не гарантируется.
- Время тратится и показывается в статусе, но само по себе цель не останавливает.
- После `goal({op:"complete"})` итоговый расход текущего хода дочитывается и записывается в состояние.
- Final flush — часть CAS-сериализации: команды используют поколение, полученное после flush, поэтому пересечение бюджета не ломает `complete`, `pause`, `drop` или смену budget.
- При resume новый `usageBaseline` берётся из текущего публичного `session.get()`, поэтому расход pause-периода не приписывается цели.
- Если доступен `tool.execute.after`, после каждого tool (кроме `goal`) выполняется расход; budget steer дедуплицируется по поколению.

### Ожидание человека

Подавление автопродолжения действует только после скрытого продолжения, в котором модель не вызвала инструменты:

1. Цель остаётся активной.
2. `waitingUser=true`.
3. Следующий ручной prompt завершает свой ход и снова разрешает скрытые продолжения.
4. Первый видимый objective под это правило не попадает.

Проверка `goal.continuationModes` не выполняется: такого публичного поля в OpenCode V2 нет. Этот параметр остаётся platform limit.

### Динамический инструмент `goal`

Инструмент не зарегистрирован всегда. `refreshGoalTool` регистрирует его, если адаптер видит хотя бы одну незавершённую цель или активное guided-интервью. Когда таких состояний не осталось, инструмент удаляется.

- Без цели и без интервью инструмент отсутствует.
- При одном цикле без цели инструмент отсутствует.
- Во время guided-интервью доступен `op:"create"`.
- При активной цели доступны `get`, `complete`, `resume`, `drop`, `todo`.
- После завершения последней цели инструмент удаляется.

**Публичное ограничение V2:** решение о регистрации считается на уровне экземпляра адаптера, а не отдельно для каждой сессии. Если goal есть в другой сессии, инструмент может быть виден и здесь. Сам инструмент всегда проверяет `sessionID`; `op:"create"` разрешён только в текущем guided-интервью и не создаёт цель из-за чужого state. Это не динамика отдельной сессии как в OMP.

## `/loop`

### Счёт и видимость

- `/loop N` делает первый ход и ещё N видимых переотправок.
- Повтор тела отправляется обычным `session.prompt` с `delivery="steer"`.
- Ручной prompt выше отметки пользователей заменяет тело. Если ручной ход уже завершён, он считается текущим ходом цикла.
- Старый транскрипт ниже отметки не становится новым телом.
- Цикл без тела ждёт следующий ручной prompt; он же выполняет первый ход.

Для активного цикла с телом лимит итераций и дедлайн проверяются до следующей отправки, после условия, после compact и после паузы между итерациями. Из-за проверки дедлайна после паузы цикл не отправит следующий prompt за уже прошедшим сроком. В режиме ожидания тела дедлайн сам по себе не отменяет ожидание ручного prompt.

### Условия

Условие выполняется через `bash -lc` в каталоге, полученном из `session.get().location.directory`. После каждого выполнения каталог обновляется из живой сессии.

| Код | `--while` | `--until` |
|---|---|---|
| `0` | продолжать | остановить |
| `1` | остановить | продолжать |
| `>1` | ошибка, цикл выключить | ошибка, цикл выключить |
| таймаут | ошибка, цикл выключить | ошибка, цикл выключить |

Условие проверяется после выполненного хода, не до первого. Повторный `/loop` или `/loop off` снимает loop token и прерывает ещё работающее условие; старый драйвер не сможет отправить следующий prompt.

### Остановка

- Повторный `/loop` с любыми аргументами сначала выключает текущий цикл и только потом разбирает аргументы.
- `/loop off`, `/loop stop` и `/loop clear` — алиасы снятия. Без активного цикла они ничего не меняют.
- Прерывание хода переводит loop в `paused`, но оставляет его включённым. Следующий ручной prompt заменяет тело.
- Прерывание не превращает цикл в `off`; для полного снятия нужен `/loop` или `/loop off`.

### Цель и цикл вместе

Цель и цикл хранятся независимо в одном state envelope.

- Первый objective цели всё равно отправляется, даже если цикл уже активен.
- После первого хода цикл владеет очередью, пока он не выключен.
- Скрытые продолжения цели в это время не отправляются.
- После снятия цикла активная цель продолжает работу.

## Plan, vibe и настройки

Любая команда `/goal ...` и `goal({op:"create"})` блокируются, если opencode2 сообщает:

- native plan или paused plan;
- vibe/vibe-director;
- активное состояние из `VIBE_STATE_DIR`.

Проверка стоит до разбора команды, поэтому в этих состояниях недоступны даже `show`, `pause`, `resume` и `drop` через `/goal`. Инструмент `goal` применяет проверку только к `op:"create"`; `get`, `complete`, `resume`, `drop` и `todo` он не блокирует.

Уже активная goal тоже перепроверяет plan/vibe перед первым objective и каждым скрытым continuation. Если режим сменился, goal переводится в `paused`, а prompt не отправляется. Это защищает от скрытого продолжения в read-only plan, но не меняет нативный агент, который TUI отправил до срабатывания hook.

Публичного `session.info.settings` с `goal.enabled` в V2 нет, поэтому адаптер не читает и не изображает поддержку этого флага. `/loop` в plan и vibe разрешён.

## Состояние V2 и восстановление

Состояние лежит в:

```text
~/.local/state/modes-station/<sessionID>.json
```

Путь меняется через `MODES_STATE_DIR`. Имя сессии для файла очищается от небезопасных символов.

Envelope имеет:

```text
version: 2
sessionID
cwd?
goal?
loop?
updatedAt
revision
ownerPid?
ownerInstance?
```

Команды читают и пишут envelope под файловой блокировкой. Запись идёт во временный файл с правами `0600`, затем атомарно заменяет state-файл. Обычные изменения через `mutateEnvelope` и `patchMode` увеличивают `revision`.

Для совместимости state-файл также содержит плоские поля старого API одного режима. Это только проекция:

- вложенные `goal` и `loop` остаются источником истины;
- незавершённая цель имеет приоритет в плоских полях;
- одновременно прочитать оба режима через плоскую проекцию нельзя — для этого нужны `goal` и `loop` внутри envelope.

Восстановление:

- v1 goal/loop мигрирует в v2, сохраняя те расход, время и todo, которые были в старом состоянии;
- старый `maxIterations:1000` не превращается в лимит, если `turnsLimited=false`;
- `GOAL: DONE` из v1 мигрирует в `paused`;
- после холодного рестарта активная цель другого процесса переводится в `paused`; продолжение только через `/goal resume`;
- активный или приостановленный цикл старого процесса удаляется, чтобы не остался драйвер-зомби;
- повреждённое состояние не запускает режим заново автоматически.

## Проверка

В текущем `tests/logic.test.mjs` ровно **108 проверок**. Число получено прямым подсчётом строк `ok`; оно относится к проверкам, а не к сценариям.

```bash
bun modes-station/tests/logic.test.mjs
node modes-station/tests/logic.test.mjs
```

Проверки покрывают точный разбор и единицы времени, OMP-арифметику loop, условия и bounded output, видимый первый objective, скрытые продолжения и фактический idle boundary, динамический инструмент и session guard, бюджет и конкурентный token flush, V2 envelope и одновременные goal/loop, защиты plan/vibe, catalog escalation, XML-экранирование, event reconnect/disposer, location-scoped recovery, write/lock failures, миграцию v1 и холодное восстановление.

## Установка

```bash
bin/modes-station.sh install
bin/modes-station.sh status
bin/modes-station.sh remove
```

Windows:

```powershell
pwsh -File bin/modes-station.ps1 install
```

Конфиг opencode2 берётся из `MODES_CONFIG_DIR`, затем `XDG_CONFIG_HOME/opencode`, затем `~/.config/opencode`.

После изменения `plugin/opencode/modes.ts` нужен:

```bash
opencode2 service restart
```
