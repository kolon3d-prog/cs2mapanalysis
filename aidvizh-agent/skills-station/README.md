# skills-station

Станция скиллов: хранит **копии** сторонних скиллов в своей коллекции и раскладывает выбранные
по слоям — глобальному, проектному, клиентскому или в любой указанный путь. Кастомные скиллы сюда не
попадают: они живут в своих проектах и подключаются симлинками.

## Коллекция

`collection/` — 92 скилла, скопированных из `~/.agents/skills` (только те, что пришли из маркетов;
`skills-ops`, `sysprompt`, `data-vault-ops`, `design-refs`, `fedora-windows-look` не копировались —
это своё). Источник каждого скилла записан в `collection/catalog.json`, и `verify` следит, что у всех
на месте `SKILL.md` с `name` и `description`.

Единственное исключение — наши четыре скилла `camoufox-research-{rails,deep-research,automation,ops}`
из `../camoufox-research/research/public/skills`: они лежат в коллекции не копиями, а каталогом, где
`SKILL.md` — ссылка на файл в своём репозитории (вторая копия текста разъехалась бы с источником).
В `catalog.json` у них источник `своё: camoufox-research/research/public/skills`, `verify` отдельно
сообщает о битой ссылке, а `--mode copy` разыменовывает ссылку и кладёт независимую копию.

Второй такой скилл — `spec-mode` из `../spec-station`: он тоже свой, источник `своё: spec-station/skill`,
но каталог в коллекции целиком ссылка на `skill/` станции — у спеки, кроме `SKILL.md`, есть справочники
и шаблоны, и каждый из них пришлось бы линковать отдельно. Ставит его `../spec-station` (ей же принадлежат
и слэш-команды `/spec*`, которых `skills-station` не раскладывает), а коллекция даёт ему место рядом
с остальными скиллами.

Третий свой — `jev-ops` из `../mcp-station/skill`: каталог в коллекции тоже ссылка на станцию-владельца
(запись сервера `jev` живёт в её каталоге). Скилл про то, когда звать тулы jev и как они у нас подключены
(OpenRouter, модель, цена, грабли); дизайн вопросов остаётся за официальным `typesafe-ai`, который лежит
рядом обычной копией из маркета.

Пополняется хабом (`../skills-hub`): `skills-manager install <pkg>`, потом копия в коллекцию. Через
`skills-manager` же обновляются и сами скиллы.

## Команды

    bin/skills-station.sh list                          что есть в коллекции
    bin/skills-station.sh find "запрос"                 поиск по УСТАНОВЛЕННЫМ скиллам (слои + коллекция)
    bin/skills-station.sh show <имя>                    описание и первые строки тела скилла
    bin/skills-station.sh install <имена...|all>        разложить в слой
    bin/skills-station.sh remove <имена...|all>         снять из слоя
    bin/skills-station.sh status                        что стоит в слое, что вне коллекции, битые ссылки
    bin/skills-station.sh verify                        целостность коллекции

Флаги:

- `--layer global` (по умолчанию) — `~/.agents/skills`, канонический стор агента;
- `--layer project` — `./.agents/skills` текущего каталога;
- `--layer opencode` — `~/.config/opencode/skills` (или `$XDG_CONFIG_HOME/opencode/skills`);
- `--layer claude` — `~/.claude/skills`;
- `--dir <путь>` — любой свой путь;
- `--mode link` (по умолчанию) — ссылкой на коллекцию; `--mode copy` — независимой копией;
- `--limit <N>` — сколько находок отдать (`find`, по умолчанию 10);
- `--dry-run` и `--json`;
- `--force` — заменить существующий target; перед заменой создаётся `.bak` (следующие backups получают `.bak.1`, `.bak.2`).

`find` отвечает кодом 0, когда нашлось, и 1, когда нет (пустая выдача отдаёт ближайшие похожие имена);
`show` берёт имя целиком или однозначную часть и тоже возвращает 1, если скилла нет. Поиск локальный —
сеть и база не нужны, поэтому скилл находится прямо в сессии, не дожидаясь перезапуска клиента.

**Лок записи.** Глобальный слой `~/.agents/skills` пишут двое: хаб (маркеты) и станция. Хаб держит свои
записи в файле-локе — `~/.agents/.skill-lock.json`, при `--project` `<проект>/skills-lock.json` (те же
пути считает `skills-manager`), но OS-лока поверх него не берёт: `skills CLI` пишет его обычным
read-modify-write. Поэтому станция берёт **тот же путь** под свой файл-владелец рядом с ним, создаваемый
атомарно (`wx`) и содержащий pid и время: `flock` в node нет, а атомарное создание файла есть и на POSIX,
и на Windows — приём один на обеих ОС. Сам JSON маркетов станция не трогает — там записи `skills CLI`.
Два прогона станции в слой одновременно не пишут; параллельный `npx skills add` этим локом не остановить —
он про него не знает (это граница, не баг). Лок занят живым прогоном — станция ждёт его 30 с
(`SKILLS_STATION_LOCK_WAIT_MS`) и говорит «слой занят», вместо того чтобы писать поверх; протухший лок
(pid мёртв или старше 30 минут) снимает сама. Лок берут `install` и `remove` (в `--dry-run` — не берут:
писать нечего); слои, которые хаб не пишет (`opencode`, `claude`, `--dir`), лока не требуют.

Windows — та же станция без bash: `pwsh -File bin/skills-station.ps1 ...` или двойной щелчок
`bin/skills-station.cmd` (показывает коллекцию).

## Примеры

    bin/skills-station.sh install mcp-builder skill-creator --layer project
    bin/skills-station.sh install all --layer opencode --mode copy
    bin/skills-station.sh install firecrawl tavily --dir ./vendor/skills --dry-run
    bin/skills-station.sh status --layer project

## Проверка

    bin/skills-station.sh verify      # коллекция: у каждого скилла SKILL.md с name/description
    bin/skills-station.sh status      # слой: из коллекции / вне коллекции / нет из коллекции / битые ссылки
    bats tests/station.bats           # 26 тестов: слои, link/copy, замена чужого, remove, verify, ссылка на репозиторий, лок записи в слой, PS-обёртка

тесты подменяют дом и коллекцию (`SKILLS_STATION_HOME`, `SKILLS_STATION_COLLECTION`) — реальные скиллы
не трогаются.

## На каких ОС проверено

| ОС | чем | статус |
|---|---|---|
| Linux | `bin/skills-station.sh` | проверено: 26 тестов, живой `status` по глобальному слою, установка в проектный слой |
| Windows | `bin/skills-station.ps1`, `.cmd` | проверено под PowerShell 7 на Linux (слой global → `%USERPROFILE%\.agents\skills`, ссылки делаются junction'ами); на настоящей Windows не запускалось |
| macOS | `bin/skills-station.sh` | не проверялось (машины нет); GNU-специфики в скриптах нет — `[INFERENCE]` |

Пути считаются от `$HOME` и текущего каталога, в файлах станции абсолютных путей нет (проверяется
сканером `../skills-hub/contrib/check-paths.sh`; каталог `collection/` он пропускает — там чужие копии).

## Грабли

- **Ссылка живёт, пока живёт диск.** `--mode link` (по умолчанию) экономит место и всегда отдаёт
  свежую версию, но пропадёт вместе с диском; `--mode copy` переживёт диск, зато разойдётся с коллекцией
  при обновлении — тогда просто переставь копию тем же `install`.
- **Чужой скилл на месте назначения заменяется** (`заменяю чужое` в выводе), а не сливается с ним.
- **Коллекция — снимок, а не живой источник.** Обновил скилл через хаб — скопируй в коллекцию, иначе
  станция поставит старую версию. Четыре `camoufox-research-*` стоят ссылкой — они всегда берутся
  прямо из своего репозитория.
- **`opencode` читает свой каталог**, `omp`/`pi` — `~/.agents/skills`; чтобы скилл был виден везде,
  ставь в оба слоя (или `--mode link` в global плюс ярлыки клиентов, как сделано на этой машине).
