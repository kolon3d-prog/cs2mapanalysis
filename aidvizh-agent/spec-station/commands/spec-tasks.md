Задачи спеки. Сначала прочитай `skill://spec-mode/references/tasks-and-waves.md`.
Если `skill://spec-mode` не разрешается (реестр скиллов сессии снят до установки) — читай файлы слоя
напрямую: `~/.agents/skills/spec-mode/SKILL.md` и его `references/`.

Аргумент: `$ARGUMENTS`

Разбери аргумент:

- **`<имя>`** — сгенерируй `tasks.md`, если его нет. Требование — дизайн и требования уже одобрены; без
  одобрения не генерируй. Формат: заголовок ровно `# Implementation Plan`, максимум два уровня (`1.`, `1.1`,
  без `1.1.1`), `_Requirements: 2.1, 3.3_` на гранулярные подтребования, `(P)` с `_Boundary:_` для
  параллельных, `_Depends:_` только для неочевидных связей между группами, `- [ ]*` для отложенных тестов.
  Только задачи, выполнимые кодом: деплой, документация, обучение, маркетинг, сбор фидбэка, ручной прогон —
  запрещены. Перед записью прогони гейт ревью: покрытие всех требований и исполнимость подзадач за 1–3 часа.
  Покажи задачи и спроси «Do the tasks look good?».
- **`sync <имя>`** — сверка чекбоксов с фактической реализацией: пройди по задачам, проверь код, отметь
  выполненное как `- [x]`. Чекбокс ставится только по проверенному коду, не по догадке.
- **`run <имя>`** — исполнение. Читаются `requirements.md`, `design.md` **и** `tasks.md`. Задачи
  раскладываются по волнам: зависимость задачи N от всех предыдущих — это порядок; `(P)` снимает зависимость
  только от непосредственных соседей; `_Depends:_` связывает через группы. Волна 1 — задачи без зависимостей,
  дальше по слоям; волны последовательно, задачи внутри волны параллельно.
  - **одна задача за раз**, подзадачи — до родительской;
  - статус обновляется по ходу: `- [ ]` → `- [x]`, не вышло → `- [F]` с причиной в деталях;
  - верификация — против требований, указанных в задаче, а не «выглядит нормально»;
  - завершив запрошенный объём — **стоп** и отчёт. К следующей задаче без запроса не переходить.
- **`run <имя> <номер>`** — только указанная задача (можно `2.3`).
- **`run <имя> --required`** — массовый прогон: только обязательные невыполненные задачи, опциональные
  (`- [ ]*`) пропускаются.
- **`run <имя> --sequential`** — маркеры `(P)` игнорируются, строгий порядок.

Отчёт после прогона: какие задачи закрыты, какие упали и почему, покрыты ли требования из закрытых задач,
какие задачи остались и какая волна следующая.
