# agent-bundle

Переносной набор для развёртывания ИИ.-агента на новой машине: что ставим, откуда, зачем и как проверить.
Сейчас в бандле две секции — `search` (веб-поиск и выкачка) и `Design` (дизайн-референсы для UI). Структура расширяемая: новая тема = новая папка верхнего уровня по тому же шаблону.

## Принципы

- Ключей в бандле нет. Только плейсхолдеры (`YOUR_*_API_KEY`); реальные ключи живут в env или локальных конфигах (для opencode — `~/.config/opencode/opencode.json`, для tavily CLI — `~/.tavily/config.json`, права 600).
- Скиллы не копируются в бандл: канонический стор на машине — `~/.agents/skills`, а источник на этом диске — локальная коллекция `../skills-station/collection` (кладётся в слой командой `skills-station install all`). Маркеты (`skills-manager install <pkg>`, `npx skills add`) нужны только чтобы **пополнить** коллекцию, а не чтобы ставить скиллы на машину: копия на диске переживает переезд и работает без сети, ссылка на GitHub — нет. Бандл хранит источник и команду, а не содержимое (иначе копии расходятся).
- Всё воспроизводимо: каждый пункт — либо команда, либо путь к локальному конфигу.
- Абсолютных путей нет: путь к своему инструменту вычисляется (`readlink -f ~/.agents/skills/skills-ops`, `$HOME`, `$PSScriptRoot`), иначе он мёртв на другой машине и ломается при переезде диска. Проверяется сканером: `../skills-hub/contrib/check-paths.sh . ../agent-bundle` (он же гоняется набором тестов хаба и часовой автопроверкой). Строка, где абсолютный путь законен, помечается маркером `path-guard: ok`.
- Секция = одна тема. Провайдер = один файл.

## Развёртывание с нуля (порядок)

1. Node 20+ и `npx` (скиллы и MCP-серверы запускаются через npx); сами агенты ставятся секцией `harness` ([cli-station.md](harness/cli-station.md)), общий план — `../command-center/bin/center.sh bootstrap`.
2. Скиллы: сначала локальная коллекция диска — `../skills-station` (`skills-station install all` кладёт её в `~/.agents/skills`); чего в коллекции нет — командами из README секций.
3. MCP-серверы: сниппеты из `<секция>/<провайдер>.md` добавить в `mcp.servers` в `~/.config/opencode/opencode.json` (и в `~/.omp/agent/mcp.json` для omp), ключи подставить из своего кабинета.
4. Свои инструменты: секция `harness` — симлинки, гейты подтверждения на установку скиллов, автопроверка.
5. Проверка: команды из раздела «Проверка» каждого провайдера; для `harness` — `skills-manager doctor` должен закончиться `doctor: ok`.

## Как расширять

Новая тема (например, `vault`, `design`, `dev`):

1. Создать `<тема>/README.md` с индексом: что входит, зачем, как развернуть.
2. На каждого провайдера/инструмент — отдельный `<имя>.md` по шаблону: Источник, Установка, Ключи, Что даёт, Скиллы, Проверка, Грабли.
3. Добавить строку в блок «Структура» выше.

Правило то же: без секретов, только плейсхолдеры; вместо копий — источник + команда.
