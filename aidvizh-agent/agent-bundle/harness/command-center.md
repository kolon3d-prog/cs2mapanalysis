# command-center

Центр координации проектов на диске: знает все, проверяет связи, зовёт их команды и печатает план
установки с нуля. Карта — в `registry.json` (пути относительные, абсолютных нет).

## Команды

    bin/center.sh status      # состояние каждого проекта: файлы, тесты, git, живые ссылки
    bin/center.sh doctor      # связи: симлинки в дом, MCP-регистрации в omp/pi/opencode
    bin/center.sh links       # карта связей и цепочка активации
    bin/center.sh run <проект> [...арг]
    bin/center.sh activate [имена|all] [--dry-run]
    bin/center.sh prereqs     # предпосылки: что есть в системе и чем доставить недостающее
    bin/center.sh bootstrap   # план установки с нуля: 22 шага + что остаётся руками
    bin/center.sh check       # сквозная проверка диска (наборы, что зовёт skills-hub-check.sh)
    bin/center.sh backup --to <путь> [--keep N]   # бэкап набора: архив + .sha256, ротация
    bin/center.sh restore --from <архив|каталог> --to <пустой каталог>   # распаковка в сторону + сверки копии
    bin/center.sh docs [тема] # документация системы: индекс, тема или путь к файлу

Рядом живёт сторож набора — `bin/sentinel.sh` (движок `bin/sentinel.mjs`): отвечает на то, что центр
проверить не может, потому что сам лежит на диске, — «диск DATA на месте и живы ли ссылки в `$HOME`?».
`center status` в конце печатает строку про сторожей: есть ли их юниты, включён ли таймер и чем кончился
последний прогон (спрашивает `systemctl --user show`); без systemd — честная строка, что юнитов нет.

Windows — `pwsh -File bin/center.ps1 ...` (или `powershell.exe -File ...`, если pwsh нет: обёртки под 5.1)
или двойной щелчок `bin/center.cmd`.

## Windows: без bash и без WSL

Команды проектов на Windows зовутся их же `.ps1-обёртками`: у каждого `.sh` есть сосед, и центр берёт
соседа сам (это же правило проверяет гейт доков). Шаг без пары — systemd-таймер, Linux-only станция —
честно пропускается строкой, а не падает. `bash` из PATH не берётся никогда: на чистой Windows это
заглушка WSL, которая печатает «поставь дистрибутив» и выходит с нулём (то есть врёт про успех). Если
шагу действительно нужен шелл, ищется настоящий Git Bash по абсолютному пути (`C:\Program Files\Git\bin\bash.exe`,
свой можно задать `AGGG_BASH`/`CENTER_BASH`) и проверяется ответом `GNU bash`; не нашёлся — строка
«нет настоящего bash» вместо мёртвого запуска. WSL не годится и когда дистрибутив поставлен: у него
другой `$HOME` и другой корень диска.

Предпосылки центр проверяет сам — обход PATH с расширениями `PATHEXT` и проба версии, без `command -v`
через bash. Установку блокируют только node, npm (или bun), git и gh; `bats`/`shellcheck` — тестам и
линту, о них говорится справочно.

## Проверка

    bats tests/center.bats    # 93 теста; читает реальное дерево, но ничего не меняет

## Полнота установки

Автоматизировано: агенты (`cli-station`), симлинки хаба (`skills-hub/contrib/install-links.sh`),
коллекция скиллов (`skills-station`), MCP-регистрации (`mcp-station`), персона и смена на ходу
(`prompt-station`), `/prompt` (`sysprompt`), скилл переезда (`fedora-windows-look/install.sh`),
часовая автопроверка (`skills-hub/contrib/install-units.sh`), сторож и бэкап набора
(`command-center/contrib/install-units.sh` — юниты таймеров и локальная обёртка вне диска),
сквозная проверка (`center check`).

Остаётся руками и по замыслу не автоматизируется: **ключи и логины провайдеров** (на диск не пишем;
ключи сервисов вводит `mcp-station/bin/keys.sh`), первый перезапуск клиентов, шаги самого скилла
`fedora-windows-look` (он применяется по `SKILL.md`). Предпосылки (node и прочее) не ставятся
автоматически — `center prereqs` только показывает, чего не хватает и какой командой доставить.

## Грабли

- новый проект не виден центру, пока не добавлен в `registry.json`;
- `activate` дёргает чужие установщики: где нет `--dry-run` (у `sysprompt/install.sh`), режим плана
  только показывает команду, не запуская её;
- `check` — это прогон наборов, которые зовёт `skills-hub-check.sh` (19 файлов bats из 23 на диске),
  плюс живая проверка MCP: целиком идут минуты, а не секунды;
- юниты-таймеры есть только там, где есть systemd: на Windows планировщик для центра не написан
  (сторож и бэкап запускаются руками), а у хаба команда регистрации печатается установщиком.
