# omp-zen-free

Расширение для `omp` и `pi`: снимает `403 FreeTierError` бесплатного тарифа OpenCode Go / OpenCode
Zen, когда харнесс ходит в их модели вне клиента OpenCode. One-file-патч: `fetch` внутри процесса
клиента правит атрибуцию запросов к шлюзу `opencode.ai` — то, что делает PR в самом omp
(issue #12306, PR #12326), но без пересборки бинаря.

## Что делает файл

- `User-Agent: opencode/1.18.31` (кроме запросов с OAuth-отпечатком `claude-cli/` — тот главнее);
- `x-opencode-session` канонизируется в формат `ses_<hex:12><base62:14>` (детерминированно, чтобы
  не разъезжалась привязка кэша промптов), `x-opencode-client: desktop` — если не задан;
- в JSON-теле добавляет заглушки недостающих имён инструментов (`bash`, `read`); заглушки не
  регистрируются в харнессе — если модель их позовёт, вызов упадёт, и модель отыграет;
- **закрывает выдохшийся ключ**: если шлюз ответил `401`/`402` с текстом про деньги
  (`CreditsError`, `Insufficient balance`, `Insufficient account funds`), ключ, которым ушёл запрос,
  помечается отключённым в сторе omp. omp сам на эту формулировку не переключается: его паттерны
  знают `insufficient balance` и `insufficient credits`, но не `insufficient account funds`, —
  поэтому ход падал, а следующий брал тот же ключ. Теперь следующий идёт соседним.
  Выключается `ZEN_DISABLE_BURNED=0`.

Чужие хосты не трогаются вообще; при любой внутренней ошибке запрос уходит как есть (fail open).
Наружу не уходит ничего: значение ключа расширение видит в том самом запросе, который и так отправляет,
и сверяет его со строками стора omp, чтобы найти нужную и пометить отключённой. В лог и в уведомления
ключ не попадает — только номер строки стора и причина.

**Локальная правка против gist'а (2026-09-21):** перезапись `/zen/…` → `/inference/openai/…`
выключена по умолчанию и включается только `ZEN_REWRITE_URL=1`. Живые проверки показали, что
`/zen/v1` и `/zen/go/v1` с патченными заголовками отвечают `200`, а `/inference/openai/…` — `401
Invalid credential`; перезапись ещё и ломала путь opencode-go (`/inference/openai/go/…` → `404`).
Заголовков достаточно. Если шлюз вернётся к старым правилам — включи переменную.

**Вторая локальная правка (2026-09-21):** закрытие выдохшегося ключа. Причина: шлюз отвечает
`402 … Insufficient account funds`, а классификатор omp знает только `insufficient balance` и
`insufficient credits` — на этой формулировке он не сжигает ключ и не переключается, поэтому ход
падал и повторялся тем же ключом. Замер по логам до правки: 159 обрывов хода с этой ошибкой при
12 активных ключах. Правка помечает такой ключ отключённым в сторе; отключённые omp не выбирает
(`WHERE disabled_cause IS NULL`), так что следующий ход идёт соседним. Правильное место для этого —
сам omp: у него в `error/rate-limit.ts` не хватает слова `funds` в паттернах; правка здесь — обход.

Переменные окружения:

    ZEN_INJECT_TOOLS=0    выключить добавление имён инструментов (заголовки остаются)
    ZEN_REWRITE_URL=1     включить перезапись URL (по умолчанию выключена)
    ZEN_DISABLE_BURNED=0  не закрывать ключ на отказе по деньгам (по умолчанию закрывает)
    ZEN_HEADERS_DEBUG=1   писать строку на запрос в <tmpdir>/zen-free-tier-headers.log

## Установка

Ставит два расширения: `zen-free-tier-headers.ts` — в omp и pi, `keys.ts` — только в omp
(он пишет в хранилище omp; у pi такого нет).

Linux / macOS (по умолчанию — оба клиента):

    bash install.sh              # заголовки в omp+pi, /keys в omp
    bash install.sh --omp        # только omp
    bash install.sh --pi         # только заголовки в pi

Каталоги: `${OMP_AGENT_DIR:-${PI_CODING_AGENT_DIR:-$HOME/.omp/agent}}` и
`${PI_AGENT_DIR:-${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}}`.

Windows (в том числе Git Bash — он сам позовёт PowerShell):

    pwsh -File install.ps1                 # оба клиента
    pwsh -File install.ps1 -Target omp
    pwsh -File install.ps1 -WhatIf

Расширения читаются на старте сессии: текущую сессию перезапусти.

## Мультиключи: `/keys`

omp умеет несколько ключей на провайдера и сам перебирает их (таблица `auth_credentials` в
`~/.omp/agent/agent.db`). Команда `/keys` в omp показывает и правит это хранилище:

    /keys                       список ключей (маскированно) и состояние
    /keys add opencode-go sk-…  проверить ключ бесплатной моделью и положить в хранилище
    /keys check [provider]      прогнать включённые ключи: ok / нет баланса / неверный ключ
    /keys check --prune         то же, но мёртвые (401/402) сразу отключить
    /keys disable <id> [причина]   /keys enable <id>   /keys remove <id>

То же из терминала (bun — рантайм omp):

    bun keys.ts list
    bun keys.ts add opencode-go sk-...
    bun keys.ts check --prune

Мёртвые ключи лучше отключать, а не удалять: аккаунт пополнят — вернёшь `/keys enable <id>`
(удаление стирает ключ из хранилища). Проверка ходит только на `opencode.ai` и тратит один
маленький запрос к бесплатной модели; `OMP_KEYS_SKIP_PROBE=1` отключает пробу.

## Ключи

Ключ OpenCode берётся клиентами сам, из своих хранилищ (в набор и архив ключи не попадают):

- **omp** — `/login` в интерфейсе (провайдер OpenCode Go или OpenCode Zen, вставляешь ключ) или
  `--api-key`/`OPENCODE_API_KEY` на запуск. В хранилище omp ключи лежат в `~/.omp/agent/agent.db`
  (таблица `auth_credentials`, провайдеры `opencode-go` / `opencode-zen`).
- **pi** — `~/.pi/agent/auth.json`:
  `{"opencode": {"type": "api_key", "key": "…"}, "opencode-go": {"type": "api_key", "key": "…"}}`
  (имена провайдеров pi: `opencode` — Zen, `opencode-go` — Go) либо `OPENCODE_API_KEY` в окружении.

У бесплатных аккаунтов бывает пустой/отрицательный баланс: шлюз отвечает `401 CreditsError` или
`402 Insufficient account funds` — это не гейт и не патч, а состояние аккаунта, пробуй другой ключ.
Такой ключ расширение закрывает само, на первом же отказе в реальном запросе: в `list` он появится
как `ОТКЛЮЧЁН (запрос <дата>: нет баланса (402))`. Аккаунт пополнят — вернёшь `/keys enable <id>`.
Отключённые omp не выбирает, поэтому ход перестаёт падать на них повторно.

## Проверка

    bats tests/install.bats      # 12 тестов: установка, патч заголовков/url/инструментов на подменённом
                                 # fetch, закрытие выдохшегося ключа на 402, выключатель (сети нет)

Закрытие ключа проверяется на своей базе: тест поднимает стор во временном файле, подменяет fetch
ответом `402 … Insufficient account funds` и убеждается, что закрылся ровно тот ключ, которым ушёл
запрос, а соседний не тронут. Живьём то же можно прогнать на **копии** стора, не трогая рабочие ключи:

    cp ~/.omp/agent/agent.db /tmp/storecopy.db
    OMP_KEYS_DB=/tmp/storecopy.db bun <скрипт с подменённым fetch>   # и убрать копию после

Живая проверка патча 2026-09-21 (перезапись выключена): `opencode-go/deepseek-flash`,
`opencode-go/omen-alpha`, `opencode-zen/nemotron-3.5-lightning-free` отвечают `200`; без патча
шлюз отвечает `403 FreeTierError` (проверено апстримом в issue #12306).

любой момент — тогда расширение просто перестанет помогать (или начнёт 403), и его надо будет
либо обновить, либо снять. Аккаунт и квота — твои.
